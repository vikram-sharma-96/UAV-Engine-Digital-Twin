# AeroTwin AI — Engineering Handover & Demonstration Guide

## 1. System Overview

**AeroTwin AI** is an AI-enabled, real-time digital twin system engineered for health monitoring, anomaly detection, and predictive maintenance of UAV internal combustion engines (Rotax 912 / PT900 1211cc 4-cylinder boxer engine class).

The platform was built from first principles with **zero external cloud dependencies**, running entirely on local edge hardware (tested on 4 GB RAM, dual-core Intel Core i3 class machines).

---

## 2. Quick-Start Guide for Hackathon Judges & Evaluators

### Option A: Complete Desktop Application (One Command)
```bash
# Builds the production static bundle and launches in an isolated desktop window
npm run build
npm run desktop
```

### Option B: Local Development Server (Live HMR)
```bash
npm run dev
# Open browser at: http://localhost:4321
```

### Option C: Standalone Headless Simulation & Streaming API
```bash
# Starts the high-performance native HTTP server & SSE real-time telemetry streamer
npm run server
# Access state snapshot:   curl http://localhost:4321/api/engine/state
# Access health analytics: curl http://localhost:4321/api/health
# Stream live telemetry:   curl -N http://localhost:4321/api/telemetry/stream
```

### Option D: Run Full Automated Verification Suite
```bash
npm run test
# Executes 27 automated tests across 13 engineering suites in ~1.5 seconds
```

### Option E: Run Performance & Memory Benchmark
```bash
npm run benchmark
# Simulates 10,000 real-time cycles (~167 minutes of flight) at 1,500+ steps/sec
```

## 3. Five-Minute Hackathon Demonstration Script

Follow this script to demonstrate the capabilities of AeroTwin AI to judges:

| Step | Time | Screen / Action | What to Explain to Judges |
| :--- | :--- | :--- | :--- |
| **1. Baseline Overview** | 0:00 - 0:45 | Navigate to `/overview` | Show nominal cruise telemetry (5200 RPM, 77°C CHT, 4.2 bar oil pressure). Explain that telemetry is generated by a **physics-informed mean-value engine model** executing coupled thermodynamics, rotational inertia, and ISA atmospheric calculations. |
| **2. Digital Twin Observer** | 0:45 - 1:30 | Navigate to `/digital-twin` | Highlight the **Observer Architecture**. Explain that an analytical twin computes expected state $\mathbf{y}_{exp}$ in real-time. Show the residual vector ($\mathbf{R} = \mathbf{y}_{meas} - \mathbf{y}_{exp}$) remaining near zero during nominal flight. |
| **3. Progressive Fault Injection** | 1:30 - 2:30 | In UI or via API (`POST /api/fault/inject`) select **Bearing Wear** or **Thermal Anomaly** | Show progressive degradation over time (not a binary switch). Observe high-frequency vibration harmonics rising from $0.8\text{ mm/s}$ to $> 2.4\text{ mm/s}$. Point out the digital twin residual spiking on the vibration channel while RPM remains governed. |
| **4. Grounded AI Copilot** | 2:30 - 3:30 | Navigate to `/predictions` | Click the quick prompt: *"Analyze Health State"*. Show the Copilot response streaming in. Point out that the AI **never hallucinates**: it cites the exact residual $\Delta v = +1.6\text{ mm/s}$, references the ISO 10816 vibration threshold, and identifies bearing defect frequency without external cloud API calls. |
| **5. "What-If" Counterfactual** | 3:30 - 4:15 | On `/predictions` or via API | Click *"Evaluate What-If: Reduce Throttle to 65%"*. Show the sandbox simulation projecting engine life extension and temperature reduction by 14°C **without mutating live flight telemetry**. |
| **6. Data Export & Wrap-up** | 4:15 - 5:00 | Click *"Export Dataset"* or `GET /api/dataset/export` | Download the CSV dataset containing ground-truth physics labels, measured telemetry, and fault tags ready for training external ML models. |
